# Service for professional graphs

Рабочая версия 0.4 сервиса построения профессиональных графов по вакансиям.

Сервис работает без нейросетей: входные вакансии обрабатываются обычным Python-кодом, словарями и явными правилами. Одинаковые входные файлы и версии словарей дают одинаковые результаты, кроме автоматически созданных имени запуска и даты папок дополнений.

## Что уже работает

- чтение локального JSON с вакансиями;
- минимальный коннектор официального API HH.ru;
- сохранение исходных поисковых ответов HH с временем и SHA-256;
- сохранение полной исходной карточки и SHA-256;
- постоянная история новых, изменённых и неизменившихся версий вакансии;
- связь вакансии со всеми поисковыми запросами, по которым она найдена;
- исключение архивных и недоступных вакансий из текущего графа без удаления истории;
- очистка HTML, определение языка и разбиение текста на отдельные фрагменты;
- распознавание разделов «Требования», «Обязанности», «Будет плюсом», «Условия» и «О компании» на русском и английском;
- определение Junior, Middle и Senior по простым проверяемым признакам;
- явная отметка конфликта грейда;
- поиск известных нод по словарю и синонимам;
- хранение каждого места, где найден навык: раздел, фрагмент, позиция, язык и использованный синоним;
- различение обязательных, желательных, необязательных и явно отрицаемых навыков;
- распознавание профессиональных конструкций «действие + объект»;
- разложение составных фраз вроде «разработка и внедрение ML-моделей» на отдельные кандидаты для проверки;
- временный расчёт `count` по уникальным вакансиям с весом раздела и ограничением доли одного работодателя;
- объединение одинаковых source ID и отчёт вероятных перепубликаций;
- частотный список неизвестных биграмм и триграмм без автодобавления в граф;
- отдельный строгий JSON для каждого грейда;
- простые безопасные SVG-шаблоны и `image_dictionary.json`;
- контрактный `course_dictionary.json` с пустыми списками;
- проверка графов и связности трёх продуктовых слоёв;
- демонстрационный сквозной запуск и автоматические тесты.

## Что пока является заглушкой

- коэффициенты формулы `count`;
- правила определения грейда и решение конфликтов;
- полноценная профессиональная иерархия;
- автоматическое решение по вероятным перепубликациям — сейчас они только попадают в отчёт;
- поиск и оценка учебных материалов;
- итоговый дизайн SVG и список разрешённых библиотек иконок;
- продвинутая проверка перепубликаций вакансий;
- распознавание нестандартных авторских заголовков разделов и повторяющихся рекламных блоков без заголовка;
- база данных, серверное API и планировщик.

Заглушки явно отмечаются в `validation_report.json`, `coverage.json` и файлах правил. Новые неизвестные ноды автоматически в граф не добавляются.

## Быстрый запуск демонстрации

Нужен Python 3.12 или новее.

```powershell
cd "C:\Users\titor\Desktop\service for professional graphs"
$env:PYTHONPATH = "$PWD\src"
python -m graph_service run --config examples/profession_config.json --runs-root data/runs
```

Либо запустить:

```powershell
.\run_demo.ps1
```

Результат появится в `data/runs/<run_id>/`.

## Основные результаты запуска

```text
data/runs/<run_id>/
├── input/
├── raw/
│   ├── search/
│   └── vacancies/
├── normalized/
├── evidence.json
├── phrase_evidence.json
├── phrase_candidates.json
├── grade_decisions.json
├── vacancy_versions.json
├── scoring_components.json
├── unclassified.json
└── output/
    ├── profession_graphs/
    ├── profession_graph_node_images_<date>/
    ├── profession_graph_node_courses_<date>/
    └── validation_report.json
```

Между запусками версии сохраняются отдельно в `data/history/vacancies/` и никогда не перезаписываются новой карточкой.

## Пробный запуск через HH.ru

Сначала замените контактную почту в `examples/hh_profession_config.json`. Если у проекта есть токен приложения, передайте его через переменную среды, а не записывайте в JSON или код:

```powershell
$env:HH_API_TOKEN = "project-token"
$env:PYTHONPATH = "$PWD\src"
python -m graph_service run --config examples/hh_profession_config.json --runs-root data/runs
```

Сборщик не обходит CAPTCHA, закрытые страницы и ограничения источника. Для первой проверки рекомендуется оставить `max_pages: 1`.
Автоматические тесты HH-коннектора используют имитацию ответов API; реальный сетевой запуск намеренно не выполнялся без проектной контактной почты и решения по токену.

## Где менять правила

- `dictionaries/canonical_nodes.json` — канонические ноды, синонимы и пути;
- `rules/` — заготовки утверждаемых правил;
- `examples/profession_config.json` — временные коэффициенты и политика конфликтов;
- `src/graph_service/graph/grades.py` — текущая прозрачная логика грейдов;
- `src/graph_service/graph/scoring.py` — текущая прозрачная формула `count`.
