# Service for professional graphs

Рабочая версия 0.9 сервиса, который собирает вакансии, выделяет навыки и строит профессиональные графы по Junior, Middle и Senior.

Сейчас весь путь можно проверить на демонстрационных данных или автоматически собрать реальные вакансии через публичные HTML-страницы HH и открытый API «Работа России» без регистрации и ключа. Официальный API HH остаётся отдельным режимом для запуска с токеном.

## Что реализовано

- каталог из 15 IT-профессий; количество профессий и поисковые запросы задаются в JSON;
- локальные JSON-файлы вместо базы данных;
- сборщик официального API HH с пагинацией, повторами, сохранением сырых ответов и историей версий;
- автоматический HTML-сборщик HH без API: период, общий лимит вакансий, фильтрация названий, повторы и корректная остановка при CAPTCHA;
- автоматический сборщик открытого API «Работа России»: поиск по профессии, периоду и необязательным кодам регионов;
- безопасный импорт прямых публичных страниц `https://hh.ru/vacancy/<id>` без токена и без обхода ограничений;
- очистка HTML, разделы вакансии, обязательность, отрицания и исключение рекламных блоков;
- канонический IT-словарь из 143 нод, синонимы и доказательства каждого совпадения;
- кандидаты новых нод без автоматического изменения утверждённого словаря;
- грейд по опыту, зарплате или их комбинации; пороги вынесены в настройки;
- отдельный отчёт по конфликтам грейда;
- согласованная формула `count`: доля уникальных вакансий грейда, где найден навык, в процентах;
- три строгих JSON-графа: Junior, Middle и Senior;
- SVG пяти типов, словарь изображений и файл лицензии;
- словарь учебных материалов из официальных источников и отчёт покрытия;
- локальная страница с двумя рабочими источниками: HTML-парсер HH и открытый API «Работа России», плюс проверка последнего результата;
- необязательная интеграция DeepSeek, Gemini, OpenAI и совместимого API для предложений новых нод. AI ничего не добавляет автоматически и не получает сырые вакансии;
- автоматические тесты и проверка целостности готовой папки.

## Самый простой запуск

Нужен Python 3.12 или новее.

Один раз установите проект и сетевые зависимости:

```powershell
python -m pip install -e .
```

Полная демонстрация с тестами:

```powershell
cd "C:\Users\titor\Desktop\service for professional graphs"
.\run_first_version.ps1
```

Локальная страница управления:

```powershell
.\run_web.ps1
```

Откроется `http://127.0.0.1:8765`. Страница доступна только на этом компьютере.

## 15 стартовых профессий

```powershell
$env:PYTHONPATH = "$PWD\src"
python -m graph_service list-professions
```

В каталог входят Python, Java, Frontend, Fullstack, .NET, C++, Mobile, DevOps, QA, системный и бизнес-анализ, Data Analytics, Data Engineering, Data Science и ML Engineering.

Создать настройку для одной профессии:

```powershell
python -m graph_service init-config `
  --profession python_developer `
  --output data/configs/python_developer.json
```

Названия, псевдонимы, запросы HH, регионы, период и число страниц лежат в `dictionaries/professions.json`.

## Формула count

Для каждого грейда и навыка:

```text
count = число уникальных вакансий с навыком / число всех вакансий профессии этого грейда × 100
```

Повтор навыка внутри одной вакансии не увеличивает `count`. Раздел, обязательность и уверенность сохраняются в `scoring_components.json` для проверки, но не меняют согласованный процент.

## Грейды

В `grade_rules` доступны режимы:

- `experience` — по структурированному опыту HH и годам в тексте;
- `salary` — по зарплате;
- `experience_then_salary` и `salary_then_experience` — основной и запасной признак;
- `combined` — оба признака вместе;
- `signals` — слова Junior, Middle, Senior, Intern и Lead.

Границы лет и зарплат, валюта и политика конфликтов задаются в конфигурации. Intern попадает в Junior, Lead — в Senior, но уточнение сохраняется в отчёте.

## Автоматический сбор без ключа

Запустите локальную страницу:

```powershell
.\run_web.ps1
```

Выберите профессию, период и число страниц, затем нажмите **«Собрать вакансии автоматически»**. Программа сама берёт поисковые фразы выбранной профессии из каталога, обращается к официальному открытому API «Работа России», удаляет повторы и строит результат.

То же самое из командной строки:

```powershell
$env:PYTHONPATH = "$PWD\src"
python -m graph_service public-search `
  --profession python_developer `
  --period-days 30 `
  --max-pages 2
```

Одна страница содержит до 100 вакансий на каждый поисковый запрос профессии. Источник данных: [портал «Работа России»](https://trudvsem.ru); ссылка на источник сохраняется в данных запуска.

## Автоматический сбор HH без API

Сборщик открывает обычную HTML-страницу поиска HH, извлекает прямые ссылки на вакансии и разбирает JSON-LD `JobPosting` внутри каждой карточки. Изменяемые селекторы `data-qa` используются только как запасной путь. Перед построением графа вакансии ограничиваются периодом и проверяются на соответствие выбранной профессии по названию.

На локальной странице выберите профессию, период, число страниц, лимит и регион в карточке **«Вакансии HH.ru»**, затем нажмите **«Собрать вакансии с HH.ru»**.

```powershell
$env:PYTHONPATH = "$PWD\src"
python -m graph_service hh-requests `
  --profession python_developer `
  --period-days 30 `
  --max-pages 3 `
  --max-vacancies 50
```

`--max-vacancies` задаёт общий лимит уникальных вакансий для профессии, а не лимит на каждую поисковую фразу. Код не обходит CAPTCHA: при ограничении со стороны HH текущий сбор останавливается, а состояние запроса записывается в результат.

## Ручной просмотр HH без токена

Откройте обычный поиск HH в браузере, скопируйте прямые ссылки на подходящие вакансии вида `https://hh.ru/vacancy/123456`, вставьте по одной ссылке в строку и нажмите **«Собрать публичные страницы HH»**. За один запуск принимается до 100 ссылок.

То же самое из командной строки:

```powershell
$env:PYTHONPATH = "$PWD\src"
python -m graph_service hh-public `
  --profession python_developer `
  --url "https://hh.ru/vacancy/123456" `
  --url "https://hh.ru/vacancy/234567"
```

Сервис не обходит CAPTCHA, не перебирает страницы поиска и не открывает рекламные переходы. Если HH ограничивает просмотр, сбор останавливается с понятной ошибкой. Для содержательного результата вручную подберите вакансии разных грейдов — ориентиром для первой проверки будут хотя бы 10–15 ссылок на Junior, Middle и Senior. Одна-две ссылки проверяют импорт, но не позволяют построить три полноценных графа.

## Официальный API HH с токеном

После одобрения заявки секреты задаются только через переменные среды:

```powershell
$env:PYTHONPATH = "$PWD\src"
python -m graph_service init-config `
  --profession python_developer `
  --output data/configs/python_developer_hh_api.json `
  --force
$env:HH_USER_AGENT = "ProfessionalGraphs/0.9 (mlprofessionalgraphs@gmail.com)"
$env:HH_API_TOKEN = "полученный_токен"
python -m graph_service hh-probe --config data/configs/python_developer_hh_api.json --limit 5
```

Для этой команды нужен отдельный конфиг с `source.type = "hh"`; HTML-конфиги `hh_requests` для неё не подходят. Токен не нужно записывать в JSON, код или Git. Сборщик не обходит CAPTCHA и ограничения HH.

## Необязательные AI-кандидаты

AI выключен по умолчанию. Чтобы его включить, в `ai` указываются `provider` и `model`, а ключ хранится в переменной `PROFESSIONAL_GRAPHS_AI_KEY`. Затем:

```powershell
python -m graph_service ai-suggest `
  --config examples/profession_config.json `
  --run-dir data/runs/<run_id>
```

Команда отправляет только неизвестные фразы и частоту, сохраняет `ai_candidates.json` и никогда сама не правит основной словарь.

## Что пока не окончательное

- HTML-сбор HH зависит от публичной разметки и может быть остановлен CAPTCHA; для гарантированного долгосрочного доступа предпочтителен официальный API после получения токена;
- пороги грейдов и политика конфликтов остаются настраиваемыми;
- 143 ноды — стартовое IT-ядро, его ещё нужно утвердить и расширять по реальным данным;
- для базовых технологий используются собственные безопасные SVG-шаблоны; фирменные значки отложены;
- каталог учебных материалов расширяется по мере появления нод в реальных графах;
- вероятные перепубликации и новые профессиональные фразы требуют ручного решения;
- планировщик и база данных не добавлялись: Никита разрешил JSON и запуск по кнопке.

Краткий сценарий показа находится в `FIRST_VERSION.md`, сверка с 99 требованиями — в `TZ_COMPLIANCE.md`, а актуальные вопросы — в `QUESTIONS_FOR_NIKITA.md`.

## Автоматический сбор учебных материалов

Реализован автосбор ссылок на обучение для каждой ноды графа (навыки, технологии, методы):

- парсер Stepik (`src/graph_service/learning/parsers/stepik.py`) — бесплатные публичные курсы через официальный API `stepik.org/api/courses`; для каждого курса сохраняются язык, уровень, длительность и наличие сертификата;
- парсер Habr (`src/graph_service/learning/parsers/habr.py`) — русскоязычные статьи по названию навыка через страницу поиска habr.com;
- парсер YouTube (`src/graph_service/learning/parsers/youtube.py`) — обучающие видео «<навык> tutorial» через YouTube Data API v3; ключ читается из переменной окружения `YOUTUBE_API_KEY` (можно положить в `.env`); без ключа источник просто пропускается;
- агрегатор (`src/graph_service/learning/aggregator.py`) — собирает результаты всех парсеров, дедуплицирует ссылки по нормализованному URL и оставляет максимум 4 материала на ноду с балансировкой: сначала официальная документация, затем 2 курса Stepik, 1 статья Habr, 1 видео YouTube; если источник ничего не нашёл, его слот отдаётся следующему по приоритету;
- интеграция в конвейер — при `"auto_collect": true` в разделе `learning` конфигурации профессии собранные материалы сохраняются в папку запуска (`collected_learning_resources.json`) и объединяются со статическим каталогом перед построением словаря курсов;
- скрипт `scripts/generate_learning_catalog.py` — отдельная генерация каталога для всех нод словаря: сохраняет официальную документацию из текущего каталога, дособирает материалы парсерами, умеет проверять доступность ссылок (`--check-links`) и печатает сводку покрытия.

### Автоматический запуск одним скриптом

```powershell
.\collect_all.ps1
```

Скрипт выполняет полный цикл для всех 15 профессий. По умолчанию для каждой профессии обрабатываются до 3 страниц и до 50 уникальных вакансий за последние 30 дней:

1. подхватывает переменные из `.env`, например `YOUTUBE_API_KEY`;
2. для каждой профессии запускает автоматический сбор вакансий HH: `python -m graph_service hh-requests`;
3. находит последнюю папку запуска этой профессии в `data/runs`;
4. вызывает `scripts/generate_learning_catalog.py`: официальная документация берётся из `dictionaries/learning_resources.json`, список нод — из `<run>/input/nodes.json`, готовый набор материалов сохраняется в `<run>/learning_resources.json`.

Лимиты можно изменить параметрами PowerShell, например:

```powershell
.\collect_all.ps1 -MaxPages 5 -MaxVacancies 80 -PeriodDays 60
```

Между профессиями выдерживается пауза 10 секунд. Её можно изменить через `-PauseBetweenProfessionsSeconds`; при ошибке конкретной профессии скрипт продолжит остальные и в конце перечислит незавершённые этапы.

Тот же генератор вручную, без PowerShell:

```powershell
$env:PYTHONPATH = "$PWD\src"
$env:YOUTUBE_API_KEY = "ключ"   # необязательно: только для видео с YouTube
python scripts/generate_learning_catalog.py `
  --nodes dictionaries/canonical_nodes.json `
  --catalog dictionaries/learning_resources.json `
  --providers stepik,habr,youtube `
  --max-per-node 4
```

Без `--output` обновляется сам файл `dictionaries/learning_resources.json`; флаг `--no-collect` позволяет пересобрать файл офлайн, а `--quotas` — изменить распределение слотов между источниками.

Автосбор покрыт автоматическими тестами (`tests/test_parsers.py`, `tests/test_aggregator.py`): сетевые ответы подменяются заглушками, поэтому тесты ходят только офлайн.
