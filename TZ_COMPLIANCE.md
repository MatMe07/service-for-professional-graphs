# Сверка проекта с ТЗ, версия 0.9

Проверено по 99 требованиям из разделов 24–34 ТЗ. Статусы ниже относятся к текущей версии проекта, а не к будущей идеальной версии на полном массиве вакансий.

## Итог

- Сквозной конвейер работает: вакансии → нормализация → навыки и доказательства → грейды → `count` → три графа → SVG → учебные материалы → проверка результата.
- Есть 15 стартовых IT-профессий, параметры вынесены в JSON.
- Есть официальный API HH с токеном, ручной импорт отдельных страниц HH и автоматический резервный сбор через открытый API «Работа России» без ключа.
- Автоматический поиск по сайту HH, обход CAPTCHA и маскировка под пользователя не реализуются.
- Спорные ноды и синонимы не попадают в утверждённый словарь автоматически.

## Состояние по блокам ТЗ

| Блок | Что уже сделано | Что остаётся частичным |
|---|---|---|
| 24. Сбор вакансий | API HH, пагинация, повторы, интервалы, временные окна, User-Agent, сырые ответы, ручные публичные ссылки; автоматический открытый API «Работа России» без ключа | Автоматический сбор именно из HH ждёт токен; резервный источник содержит другой набор вакансий |
| 25. Хранение вакансий | JSON, исходная карточка, нормализованная карточка, дата, источник, запросы, статус, история версий, дедупликация | Между параллельными запусками нет блокировки файлов; старые карточки не всегда можно не скачивать повторно до запроса к API |
| 26. Подготовка текста | HTML очищается, разделы и фрагменты выделяются, язык/позиция/контекст сохраняются, рекламные блоки исключаются из расчёта | Редкие нестандартные заголовки вакансий всё равно могут потребовать ручной проверки |
| 27. Извлечение навыков | Словарь, составные фразы, обязанности/требования/преимущества, обязательность, отрицания, исходные доказательства | Неоднозначные короткие слова безопасно уходят в кандидаты; идеальная точность без утверждённых правил невозможна |
| 28. Канонизация | 143 утверждённые стартовые ноды, синонимы, отдельные кандидаты, журнал допустимых ручных операций | Нет автоматического нечёткого объединения похожих строк — оно намеренно не меняет граф без решения человека |
| 29. Построение графа | Три строгих вложенных JSON-графа, один путь на ноду, разделение `Hard skills`/`Soft skills`, проверка структуры | Содержательность графа зависит от числа и качества загруженных вакансий |
| 30. Иерархия и грейды | Junior/Middle/Senior, Intern→Junior, Lead→Senior, опыт/зарплата/сигналы, конфликты, настраиваемые пороги, сравнение графов | Цель 100–180 листьев проверяется отчётом, но не может быть гарантирована на маленькой выборке |
| 31. Вес `count` | Основная согласованная с куратором формула: процент уникальных вакансий грейда с навыком; все компоненты расчёта сохраняются | Рост/снижение навыка требует нескольких исторических периодов; сейчас есть только `main`/`niche` по порогу |
| 32. SVG | SVG генерируются, есть пять собственных шаблонов, словарь файлов, происхождение и лицензия | Фирменные логотипы технологий не подтягиваются автоматически; это снижает лицензионный риск, но выглядит проще |
| 33. Учебные материалы | Каталог из официальных источников, нормализация ссылок, проверка провайдера, словарь курсов и отчёт покрытия | Нет самостоятельного интернет-поиска курса для каждой новой ноды; неизвестные ноды попадают в отчёт покрытия |
| 34. Финальная сборка | Единая папка запуска, отчёты, три графа, изображения, материалы, входные параметры, журнал изменений и автоматическая проверка | Не для каждого служебного JSON есть отдельный файл JSON Schema; основные контракты проверяются кодом |

## Что считается готовым для первой сдачи

1. Запуск по кнопке или одной командой.
2. Демо без интернета.
3. Автоматический сбор реальных вакансий без ключа через «Работу России».
4. Полный набор выходных файлов и читаемый HTML-отчёт.
5. Явный список ограничений и спорных решений вместо скрытых догадок.

## Что нельзя честно закрыть до получения данных или решения куратора

- автоматический поиск большого массива именно HH через API без токена;
- содержательные графы по всем 15 профессиям без достаточного числа вакансий;
- подтверждение порогов грейда, списка нод и эталонного графа;
- признаки `growing`, `declining`, `obsolete` без нескольких периодов наблюдения;
- фирменные SVG и автоматический поиск учебных материалов без утверждённых источников и правил лицензирования.
